# 番茄小说工作室（DSH 版）

> 本 skill 是网文长篇创作的**全流程总纲**，与具体书无关；具体书的专属设定（必用词/世界观/人物/改稿规范/红线）放**书级 skill**（两件套模式：本 skill 管工艺，书级 skill 管专属）。
> 依赖：DSH 会话 + `dsh-novel-writer` 插件（提供 novel_* 工具）。安装：把本目录复制到 DSH 技能目录（项目 `.dsh/skills/` 或用户技能目录），新会话自动加载。

## 0. 三件套分工

| 层 | 内容 | 载体 |
|---|---|---|
| 工艺层 | 世界观问答法、章节工艺、改稿学习、批次管理（本 skill） | 本 skill |
| 书级层 | 某本书的必用词/世界观/人物/改稿规范/红线 | 书级 skill + 创作资料 |
| 工具层 | novel_* 插件工具（词表/数值/语义检测）+ Node 机检脚本 | DSH 插件 |

## 1. 全局流程总览

**建书 → 世界观 → 大纲 → 分章写 → 改稿 → 发布**，循环：

1. **建书**：novel_outline init 建创作资料六件套（创作设定/主要人物/次要人物/剧情大纲/钩子记录/创作状态卡）；novel_settings 五表（人物/地点/道具/时间线/世界观）+ novel_plot 伏笔表初始化。
2. **世界观**：先粗后细——作者口述 → AI 建**问答清单** → 逐批一问一答（见 §2）→ 转正到创作设定与设定表。
3. **大纲**：剧情大纲每章一行方向行；3 章一个情绪单元（压→小扬→爆）；每卷 1–2 次总爆发。
4. **分章写**：每章按 §3 章节工艺走完写前/写中/写后/收尾。
5. **改稿**：作者在番茄草稿箱改完发回 → 按 §4 对比学习 → 沉淀改稿规范。
6. **发布**：§5 番茄适配。

## 2. 世界观设定·一问一答法（核心方法）

> 目标：让 AI 与作者**逐条核对**设定，AI 不单方面替作者定稿。

**步骤**：
1. **建问答清单**（`创作资料/世界观问答.md`）：把待补设定拆成 50–100 个问题，按模块分组（时间轴/力量体系/势力/主角线/衔接等），每题可标 AI 倾向；
2. **逐批提问**：每批 5–7 问，**每题附 2–4 个候选答案（标推荐）**，作者逐条「选/改/自答」；候选答案让作者从「想答案」变成「挑答案」，效率最高；
3. **答录跟踪**：每条答案写回问答清单（答录表+状态表：模块×已答×待答）；作者新答案引发的新问题**从续编区续号追加**（如 Q107 起），注明由哪条答案引出；
4. **已确认结论**：把定稿结论汇总成编号清单（转正记录），冲突点当场提醒作者；
5. **转正**：确认后同步到——创作设定（总纲节）、境界/体系文件、novel_settings 五表、novel_lexicon 必用词（含替身词，防正文退回通用说法）、创作状态卡冷启动清单；
6. **读者友好层**：设定可以厚、读者不能累——每条厚设定配「读者版一句话」+「幕后细则表」+「正文呈现原则」（一次一个新词、比喻只讲一次、怪象先行设定后行）。

**要点**：AI 初期可给「全案草案」当候选素材池，但**正式结论必须逐条经作者确认**；设定文件里「待确认」与「定稿」分开标注。

## 3. 章节写作工艺（每章全流程）

### 3.1 章节文件结构（三块）

```
> 【本章评分卡】        ← 顶部引用块，发文时整块删掉
# 第N章 标题
正文……                ← 番茄≈2500 字
## 章节备注             ← 结尾四行台账
- 本章悬念：……
- 下一章：……
- 数值：……（点数/钱数/伤势变化）
- 伏笔登记：……
```

### 3.2 评分卡（11 字段，星级不许拍脑袋）

字段：核心事件（只写一件）/ 承接上章（写「接哪一句」）/ 悬念钩子（标类型 A信息差·B危机·C反转·D情感·E选择·F神秘线索，不得连续两章同型）/ 情绪任务（三章单元第几拍）/ 评论诱导（读者会争什么）/ 情绪曲线（起点→中段→落点）/ 爽点（类型｜强度★1–4｜有无铺垫）/ 亮点（可截图的原句，没有写「无」）/ 评分（D1–D5→加权→星级）/ 证据（原句≤20字+行号，缺证据分作废）/ 正文字数。

**五维加权**：D1 任务完成度 25%（删了断不断链条+信息增量≥2条）｜D2 情绪张力 25%（全外化零标签）｜D3 爽点质量 20%（三拍：压制→隐忍→爆发，情绪驱动）｜D4 记忆点 15%｜D5 文风完成度 15%（零 AI 味零硬伤钩子紧咬）。

**爽点强度**：★1 小爽（一句话回击/小漏）｜★2 中爽（一段戏胜负）｜★3 大爽（一章主爆点）｜★4 卷级爆（跨章蓄势总爆发）；全是★1 的章 D3 封顶 3 分。

**硬封印 7 条**（触一即封顶 3.0 星）：①章末无钩子或「计划宣告」结尾 ②禁词/称呼错（书级词表勿用列）③数字口径打架 ④解释性旁白≥3 处 ⑤情绪贴标签 ⑥平台红线 ⑦重复意象/场景。

**章节类型封顶**：铺垫/过渡章 ≤4.0；常规推进章 ≤4.5；爆发/高潮章才可 5.0（每卷 1–2 次）。**5 星硬门槛**：名场面+情绪峰值+开新悬念+零硬伤+可脱离上下文被记住。星级 <3.5 发前必改；连读三章 ≤3.5 停更复盘。段位：章均 ≥4.0 头部｜3.7–4.0 可签可推｜3.3–3.7 中途掉读者｜<3.0 返工别发。

### 3.3 章末钩子硬标准（平台生命线，8 条）

1. 驱动模式：爽点预告（怕错过好戏）优于求知；弱钩子升级成冲突预告（「门外站着一个人」→「门外站着的，是当年送他下狱的人」）；
2. 落点四选一：新危机 / 新代价 / 未完成动作 / 更危险的新解释；
3. 结尾四禁：太圆 / 太虚 / 太解释 / **宣告计划**（「明天我就去……」）；
4. 类型轮换：钩子类型不与上章同型，每 5 章 ≥3 种机制，「突然揭示」每 5 章 ≤2 次；
5. 响应节律：回应旧悬念+开新悬念；小悬念 1–3 章回收；高关注线 ≤3–4 条；
6. 断章三式：卡信息差 / 卡冲突转折点 / 卡倒计时将尽未尽；
7. 收尾压强：结尾张力 ≥ 中段；爆点章末让读者感知「下一章有更大回报」；
8. 四问：翻页怕错过什么？一句话说出下章期待？钩子预告了具体冲突/回报？截断停在最想知道结果的瞬间？

不过就「只改章末 150–300 字」补针，不整章重写。

### 3.4 节奏硬规则

- 一章至少「见血或见钱」（动手/见红/得点/丢脸/死人占一样）；纯查探铺垫不准成章；
- 三章内必须动手；五章内必须打脸/爆发；
- 开头不超两段进事；信息一次给完不复习；
- 结尾紧咬式（「天一亮」）优于隔夜缓冲（「明天我要去……」）；
- 升级卡节点：快的是事件密度不是层数，成长必须有代价门槛；
- 三章情绪单元「压→小扬→爆」，爆点逐轮放大，卷级总爆发叠加其上。

### 3.5 评论诱导（每章五选一，给评论区埋立场分裂）

两难选择 / 信息差（读者比主角多知道一点）/ 误解不解释 / 配角高光 / 道德灰区（作者不评价对错）。

### 3.6 写前 → 写中 → 写后 → 收尾

**写前 7 步**：①读书级改稿规范（作者风格硬清单，权威高于预设文风）→ ②查时间线台账算日期（=上章日期+事件跨越天数，写进正文相对时间与章节备注）→ ③`novel_chapter_brief` 开写包（上一章结尾承接口/大纲方向/待回收伏笔/必用词/禁用清单/六维基线）→ ④看情绪曲线本章任务 → ⑤读文风锚点+近 5 章摘要 → ⑥读上章结尾三段 → ⑦**场景级细纲**：拆 3–4 个场景，每场一行（目标/人物/关键对话/情绪落点/预估字数），相加≈目标字数。**字数不足的根因=细纲只到一句话动作，撑不起一章**。

**写中**：按细纲逐场景写（每场 400–800 字）；字数靠补事件不补描写；短句高动作少心理情绪外化；对话占比 ≥13%；必用词用表内词、替身词零出现；动笔前先定钩子落哪一式。

**写后**：①机检（字数+AI 味：四字格连用/连续句长相近/"的"密集；单段 >180 字分段；对话行 <10% 加对话）→ ②衔接九条人工自查（时间锚定/章首承接/行动动机/场景递进/情绪过渡/语序顺滑/跳转过渡/呼应递进/无重复句）→ ③插件三查（`novel_continuity_check` 衔接+禁词 / `novel_lexicon audit` 必用词+替身词 / `novel_style_check` 六维对照）→ ④`novel_summary add` 存摘要。

**收尾 7 项**：新角色三层登记（人物档案+novel_outline character+novel_settings character）/ `novel_plot` 新伏笔登记与销账 / `novel_outline hook` 钩子回填 / 记忆同步五件（创作状态卡+大纲进度+人物快照+伏笔+情绪曲线）/ 展示文件卡片 / 刷新字数统计 / 汇报（摘要+字数+AI 味+钩子类型+下批走向）等作者确认。

## 4. 番茄改稿对比学习（作者改稿是最高风格参照）

作者在番茄草稿箱改完发回时，执行：
1. 对比「AI 原稿 vs 作者改稿」，逐处拆解：删了什么、改了什么、加了什么、加的这几句有什么用；
2. 把可复现规律沉淀进书级「改稿规范.md」，格式固定：`规律一句话（可执行）` + 反面（AI 常写）+ 正面（作者改成）+ 场景 + 触发章；
3. 只记可执行可复现的规律，不记「更生动」这类空话；连续 3 章没再这么改的标「可能失效」；
4. 能机检的部分同步进 novel_settings（禁词/称呼/语用）与 novel_lexicon（必用词/替身词）；
5. 写新章前必读改稿规范、写完逐条自查旧毛病。

## 5. 番茄平台适配

- **发布节奏**：每天约 1 万字 = 4 章 × 2500 字（某章 3000 字则当天 3 章）；改稿也 4 章一停。
- **红线自查**：脏话清零或极度克制；未成年相关一个字都不能有；迷信/血祭细节克制；情绪别一路压到底（每章给正反馈对冲）；不乱码不分段。
- **追读**：8 万字后分发全靠追读率——章末钩子标准是最高优先级，钩子不过关不交付。

多书隔离：所有 novel_* 调用必须带 book=书名；必用词只登记书级层。

## 7. 批次与会话管理

- 4 章一批（批后汇报等确认）；单会话输出上限约 12 章，到量换新会话；
- 正文只落文件，对话只给摘要和文件指针；规划文件放 `番茄规划/` 子目录（防插件误解析成章节）；
- 评分卡/章节备注是施工记录，发文时整块删掉；
- 作者每次提的改稿要求，当下沉淀进书级规范——规范永远是「最新版本」。
